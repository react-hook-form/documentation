## \</> `setValues:` <TypeText>[UseFormSetValues](/ts#UseFormSetValues)</TypeText> <Since version="7.74.0" />

This function allows you to dynamically set multiple field values at once and have the options to validate and update the form state. It also accepts a callback function that receives the current form values, making it easy to derive the next state from the existing one.

### Props

---

| Name                                                                                                   |                                                   | Description                                                                                                                                                                                                                                                                                 |
| ------------------------------------------------------------------------------------------------------ | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `value`<br/><TypeText>Partial\<TFieldValues\> \| (formValues: TFieldValues) => TFieldValues</TypeText> |                                                   | An object containing the field values to update, or a callback function that receives the current form values and returns the next form values. This argument is required.                                                                                                                  |
| `options`                                                                                              | `shouldValidate`<br/><TypeText>boolean</TypeText> | <ul><li>Whether to compute if your input is valid or not (subscribed to <TypeText>errors</TypeText>).</li><li>Whether to compute if your entire form is valid or not (subscribed to <TypeText>isValid</TypeText>).</li></ul>                                                                |
|                                                                                                        | `shouldDirty`<br/><TypeText>boolean</TypeText>    | <ul><li>Whether to compute if your input is dirty or not against your `defaultValues` (subscribed to <TypeText>dirtyFields</TypeText>).</li><li>Whether to compute if your entire form is dirty or not against your `defaultValues` (subscribed to <TypeText>isDirty</TypeText>).</li></ul> |
|                                                                                                        | `shouldTouch`<br/><TypeText>boolean</TypeText>    | Whether to set the updated inputs to be touched.                                                                                                                                                                                                                                            |
|                                                                                                        | `delayError`<br/><TypeText>boolean</TypeText>     | <Since version="7.82.0" /> Opt-in flag that delays the display of the resulting validation error, using the delay (in milliseconds) configured via [`useForm({ delayError })`](/docs/useform#delayError). Only takes effect when `shouldValidate` is also set to `true`.                    |

<Admonition type="important" title="Rules">

- When using the callback form, the function receives a snapshot of the current form values and should return the next form values.

- This method does not reset the form. Use [`reset`](/docs/useform/reset) if you need to reinitialize `defaultValues`.

- Unlike calling [`setValue`](/docs/useform/setvalue) multiple times in sequence, `setValues` batches all updates into a single re-render.

</Admonition>

### Examples

---

**Basic**

```javascript
import { useForm } from "react-hook-form"

const App = () => {
  const { register, setValues } = useForm({
    defaultValues: {
      firstName: "",
      lastName: "",
    },
  })

  return (
    <form>
      <input {...register("firstName")} />
      <input {...register("lastName")} />
      <button
        type="button"
        onClick={() => setValues({ firstName: "Bill", lastName: "Luo" })}
      >
        setValues
      </button>
    </form>
  )
}
```

**Callback (derive next state from current values)**

```javascript
import { useForm } from "react-hook-form"

const App = () => {
  const { register, setValues } = useForm({
    defaultValues: {
      name: "",
      count: 0,
    },
  })

  return (
    <form>
      <input {...register("name")} />
      <input type="number" {...register("count")} />
      <button
        type="button"
        onClick={() => {
          setValues((data) => {
            return {
              ...data,
              name: "test",
            }
          })
        }}
      >
        setValues with callback
      </button>
    </form>
  )
}
```

**With options**

```javascript
import { useForm } from "react-hook-form"

const App = () => {
  const { register, setValues } = useForm({
    defaultValues: {
      firstName: "",
      lastName: "",
    },
  })

  return (
    <form>
      <input {...register("firstName", { required: true })} />
      <input {...register("lastName", { required: true })} />
      <button
        type="button"
        onClick={() =>
          setValues(
            { firstName: "Bill", lastName: "Luo" },
            { shouldValidate: true, shouldDirty: true, shouldTouch: true }
          )
        }
      >
        setValues with validation
      </button>
    </form>
  )
}
```

### Tips

---

- Top-level keys are merged shallowly. `setValues({ address: { city: "Paris" } })` replaces the whole `address` object, so `address.street` is lost. To change one nested value, spread the current values in the callback form:

  ```javascript
  setValues((values) => ({
    ...values,
    address: { ...values.address, city: "Paris" },
  }))
  ```

- Use `setValues` to fill a form from a template or a previous entry, so the user can still see what changed. If the data should become the new defaults, use [`reset`](/docs/useform/reset).

### Troubleshooting

---

<Troubleshoot>

#### A nested sibling value disappears after `setValues`

<Why>

Top-level keys are merged shallowly. Updating `{ address: { city: "Paris" } }` replaces the complete `address` object rather than merging its nested properties.

</Why>

<Fix>

Use the callback form and preserve the nested values you are not changing:

```javascript
setValues((values) => ({
  ...values,
  address: { ...values.address, city: "Paris" },
}))
```

For one nested field, [`setValue("address.city", "Paris")`](/docs/useform/setvalue) is simpler.

</Fix>

</Troubleshoot>

<Troubleshoot>

#### Errors, touched fields, or dirty state do not change

<Why>

`setValues` updates values, but validation and form-state updates are opt-in so a batch update does not do extra work by default.

</Why>

<Fix>

Pass the state updates you need:

```javascript
setValues(values, {
  shouldValidate: true,
  shouldDirty: true,
  shouldTouch: true,
})
```

</Fix>

</Troubleshoot>
